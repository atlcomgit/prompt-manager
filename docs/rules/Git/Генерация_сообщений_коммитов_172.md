# Генерация сообщений коммитов в Git Flow

## Выбор генератора

Для каждого выбранного проекта генераторы используются последовательно:

1. Kilo Code — только если `vscode.extensions.getExtension('kilocode.kilo-code')` возвращает расширение
   с `isActive === true` в текущем Extension Host.
2. Copilot — если Kilo отсутствует, неактивно, не имеет команды генерации, завершилось с ошибкой
   или не вернуло сообщение.
3. Внутренний `AiService` — если Copilot также не вернул сообщение. Его существующая политика
   настройки `promptManager.ai.enabled` и резервного текста сохраняется.

Генерация коммита не вызывает `Kilo.activate()`. Включённое, но ещё не активированное расширение
также пропускается. Проверка выполняется при каждом обращении до поиска Git-репозитория,
создания таймеров, постановки генерации в очередь и изменения поля Source Control.
Отсутствие или неактивность Kilo — штатный переход, а не пользовательская ошибка.

Установка расширения на диске не означает его доступность в текущем хосте.
`isActive` отражает выполненную активацию, а не отдельный пользовательский флаг включения.
Если VS Code требует перезагрузку после отключения, до её выполнения хост может сохранять прежнее состояние.

## Подготовка и результат

- Кнопка Git Flow передаёт выбранные проекты и `requestId`; при `includeAllChanges` сначала выполняется
  подготовка файлов к коммиту. Генерация сообщения сама не создаёт коммит.
- Все выбранные доступные проекты запускаются параллельно после общей подготовки staged.
  Внутри проекта сохраняется порядок Kilo → Copilot → внутренний генератор.
  Результаты выдаются в исходном порядке проектов; ошибка одного проекта не теряет успешные результаты остальных.
  Cleanup tokens создаются после завершения всей группы, по исходному SCM-ответу каждого проекта.
- Активное Kilo получает точный `rootUri` репозитория,
  а поиск репозитория, команды и её выполнение ограничены общим сроком 75 секунд.
- Для одного репозитория внешние генераторы используют общую очередь. Незавершившаяся после таймаута
  команда блокирует новые SCM-команды этого репозитория до своего завершения.
- Source Control очищается только после подтверждения применения сообщения в Git Flow и только
  при точном совпадении текущего поля с исходным результатом. Новый ручной текст сохраняется.
- Номер задачи и правила замены tracked-ветки фиксируются до ожидания генераторов.
  Очистка сопоставляется с исходным SCM-текстом, даже если префикс результата для Git Flow уже исправлен.

## Инструкции внутреннего генератора

- `github.copilot.chat.commitMessageGeneration.instructions` читается с resource scope выбранного проекта.
  Поддерживаются строки, объекты `{ "text": "..." }` и `{ "file": "..." }`, с сохранением порядка.
- Относительные пути файлов разрешаются от корня этого проекта, абсолютные и `~/` также поддерживаются.
  Нечитаемый файл завершает генерацию ошибкой, чтобы не выдать результат с потерянной частью правил.
- Пользовательские правила определяют формат, длину, язык и наклонение. Стандартные рекомендации
  о повелительном наклонении и 72 символах добавляются только при отсутствии пользовательских правил.
- В запрос передаётся зафиксированный `taskNumber`; без номера передаётся текущая Git-ветка проекта.
  Генератор не получает инструменты чтения файлов и не перечитывает активную задачу после переключения промпта.
- Это правила построения запроса, а не строгий валидатор произвольного естественно-языкового формата.
  При выключенном AI или ошибке LM сохраняется прежний резервный текст, который не является ответом модели.

## Предварительная загрузка документов Copilot

- Внутри общей очереди SCM обновляется `repository.status()`, затем используются только `state.indexChanges`
  выбранного репозитория. Для локальных `file:` URI выполняется `workspace.openTextDocument` без `showTextDocument`.
  Это также применимо к файлам на Node.js-хосте Tunnel; виртуальные URI остаются штатной команде.
- Не более четырёх параллельных операций и 32 кандидатов; размер обычного файла — до 1 МиБ,
  суммарный зарезервированный объём — до 4 МиБ. Первые 8192 байта проверяются на NUL, как в Copilot.
  Эти пределы действуют отдельно для каждого репозитория.
  Пропускаются уже открытые документы, удаления, бинарные и неподдерживаемые типы, отсутствующие файлы,
  символические ссылки, каталоги и пути за пределами корня репозитория. Тексты документации допустимы.
  Имена с подстрокой `test` загружаются на общих условиях: фильтр резервного контекста здесь не применяется.
- На подготовку отводится до пяти секунд внутри общего лимита Copilot. Ошибки файлов или обновления статуса
  не запрещают штатную команду. При дедлайне подготовки останавливается запуск новых открытий.
  Уже начатые `openTextDocument` не принимают token и могут завершиться позднее.
- Общая отмена или hard timeout запрещают поздний запуск SCM-команды после подготовки.
  Предварительная загрузка не меняет SCM input, индекс, файлы, инструкции и состав контекста Copilot.
  Ограничения загрузки не являются исключениями из контекста: оставшиеся файлы читает штатная команда.
- Copilot Chat 0.74.0 пропускает проверочное чтение бинарности для URI из `workspace.textDocuments`.
  Измеренный медленный запуск: 21 последовательное чтение — 10,855 с, 21 открытие — 12,047 с;
  это ожидание VS Code API. Предварительная загрузка переносит открытия в ограниченную параллельную группу.
  После предварительной загрузки замер в новом Extension Host: 21 документ за 4,189 с,
  вся команда с подготовкой — 7,980 с вместо 27,745 с; ошибок и отмены нет, применение результата подтверждено.
- Исключение семи test-файлов из загрузки сопровождалось регрессией: 14 документов за 3,066 с,
  команда с подготовкой — 15,136 с; ответ модели почти прежний: 1,308 с вместо 1,292 с.
  Непрогретые документы остаются последовательному пути Copilot; время каждого файла в этом запуске не измерялось.
  Возврат test-файлов в загрузку проверяется автоматически; восстановление прежнего времени требует нового замера в хосте.
- Kilo Code 7.8.27 использует собственный backend `/commit-message`, а не документы VS Code.
  Его команда принимает rootUri, но не внешний список файлов или prompt; используется собственный commit_message.prompt.
  Предварительная загрузка Copilot к Kilo не применяется. Она выполняется только при переходе на Copilot.

## Компактный контекст и длительность

- Перед выбором генератора выполняется `git diff --cached --quiet`, без рабочего diff, untracked и истории.
  Штатная команда `github.copilot.git.generateCommitMessage` не принимает список файлов для фильтрации;
  она продолжает собирать свой контекст самостоятельно.
- Подробный контекст Prompt Manager нужен только после неуспеха обоих внешних генераторов,
  если включён `promptManager.ai.enabled`. При выключенной настройке сохраняется прежний резервный текст.
- Метаданные staged читаются с NUL-разделителями, размеры Git-объектов — пакетно, без чтения содержимого.
  Файлы с подстрокой `test` в имени без учёта регистра исключаются до проверки размеров: ни содержимое,
  ни имя не попадают в metadata/summary. Каталоги не учитываются: `TestHelper.ts` исключён, `tests/helper.ts` допустим.
  Если весь набор исключён, внутренний AI не вызывается; для проекта возвращается ошибка с завершением ожидания.
  Это фильтр только собственного резервного контекста, а не предварительной загрузки или запросов Copilot и Kilo.
  Обе версии файла должны быть не больше 64 КиБ. Удаления учитываются по старой версии;
  символьные ссылки и submodule остаются только в перечне изменений.
- Выбираются до 6 небольших файлов кода, включая C/C++, с патчем до 1800 символов на файл.
  Документация, lock-файлы и минифицированные bundles не имеют приоритета кода.
  Если текстовых патчей кода не получено, выбираются до 2 минимальных текстовых файлов, до 1000 символов каждый.
  Неизвестные расширения проверяются после известных текстовых. Бинарные патчи пропускаются.
- Вывод одной команды патча ограничен 16 КиБ; итоговый контекст — 12 000 символов,
  включая краткий перечень файлов с исключённым содержимым. Отбор не меняет Git-индекс и рабочие файлы.
  Патчи используют корневой literal pathspec; внешние diff-драйверы и textconv отключены.
- Поиск сходства переименований не выполняется: перенос представлен удалением и добавлением.
  Полный сбор контекста отчётов остаётся отдельным сценарием.
- С `promptManager.debugLogging.enabled` в канале Prompt Manager доступны события
  `gitOverlay.commitMessage.timing`: `stageAll`, `stagedCheck`, `kilo`, `copilot`,
  `fallbackContext`, `internal`, `postMessage`. Записываются длительность и время от начала обработки host.
  `copilot` включает всю команду с её подготовкой, а `postMessage` — лишь отправку, не отрисовку.
  События `generateCommitMessage.delivery` связывают выдачу cleanup token и React-подтверждение его применения;
  при отсутствии подтверждения замер отрисовки не считается завершённым. Исходники и ответы в метрики не попадают.
- `generateCommitMessage.copilot.timing` различает начало, отмену по deadline и завершение команды.
  Фаза `document-prefetch` показывает время, число открытых документов и ошибок, зарезервированные байты и исход.
  Действующие пределы Copilot: отмена через 30 секунд, прекращение ожидания через 35 секунд.
  Подготовка внутри Copilot также входит в этот интервал; отменённый запрос не считается успешной генерацией.
- `[ai-request] label=generate-commit-message` показывает чтение инструкций, выбор модели, чтение каталога,
  отправку и ответ отдельно. Резервный выбор повторно использует один снимок доступных моделей,
  сохраняя проверку бесплатности; измерения запроса Copilot не включают всё предварительное ожидание.

## Реализация и проверки

- `src/services/gitService.ts`: `generateCommitMessageViaKilo`, `generateCommitMessageViaCopilot`,
  `prefetchCopilotCommitDocuments`, общий жизненный цикл `generateCommitMessageViaScmInput` и очистка результата.
- `src/providers/editorPanelManager.ts`: обработчики `gitOverlayGenerateCommitMessage`
  и `gitOverlayCommitMessagesApplied`.
- `tests/gitService.test.ts`: пропуск отсутствующего/неактивного Kilo без побочных действий,
  повторная проверка активности, таймауты, очередь, точный репозиторий и сохранность Source Control.
  Отбор контекста проверяется на изолированных Git-репозиториях: staged/unstaged, размеры,
  бинарные файлы, необычные пути, вложенные каталоги, минимальная документация и ограничение вывода.
  Предварительная загрузка проверяется с реальными временными файлами, mock API и управляемыми Promise:
  параллельность, лимиты, staged scope, кеш, ошибки, отсутствие вкладок и поздних действий после отмены/таймаута.
- `tests/editorPanelManager.test.ts`: одиночная и групповая генерация, переход к Copilot,
  внутренний резервный результат, `requestId`, номер задачи и подтверждение очистки; одновременный старт,
  независимый fallback, обратный порядок завершения, частичный успех и правильные raw SCM cleanup tokens.
- `tests/promptManagerOutput.test.ts`: прохождение метрик через реальный output-фильтр и debug-настройку.
- `tests/aiService.test.ts`: объектные и файловые инструкции, scope проекта, taskNumber, выбор free-only модели,
  повторное использование каталога, отключённый AI, ошибка файла и освобождение cancellation source.
- `tests/gitOverlay.test.ts`: состояния кнопок, групповые действия и правила результата Git Flow.
