# Аккаунты Codex, Claude Code и Copilot

Страница **Аккаунты** заменяет прежнюю Copilot Premium Usage. Она объединяет ручной выбор профилей Codex
и Claude Code с существующим выбором GitHub Copilot. Блоки показываются только при наличии соответствующих
расширений. Страница имеет собственную вертикальную прокрутку, если карточки не помещаются по высоте.
Рядом с доступным временем сброса показывается обратный отсчёт в днях и часах (для коротких периодов — также
в минутах), обновляемый раз в минуту без дополнительных запросов; истёкшие сроки не отображаются как будущие.

Старая команда `promptManager.copilotUsageDetails` сохранена как совместимый псевдоним команды
`promptManager.accounts`.

## Видимость блоков

- Codex показывается при наличии `openai.chatgpt`, Claude Code — при наличии `anthropic.claude-code`,
  Copilot — при наличии `github.copilot-chat` или `github.copilot`.
- Профили Codex создаются (и копия `auth.json` попадает в SecretStorage) только при установленном `openai.chatgpt`;
  если расширение установлено после запуска окна, инициализация и индикатор Codex появляются без перезагрузки.
- Статус-бар содержит отдельные компактные индикаторы Codex и Claude с оставшимися лимитами.
  Отдельного индикатора Copilot нет: кредиты Copilot показываются на странице «Аккаунты».

## Профили и несколько окон

- Список профилей Codex и Claude Code хранится в `globalState` и общий для всех окон VS Code. Перед каждым
  изменением и при построении страницы он перечитывается: профиль, добавленный, переименованный или удалённый
  в одном окне, не теряется и не возвращается при обновлении страницы в другом.
- «Выбрать» спрашивает подтверждение; отмена возвращает странице актуальные данные, кнопки не блокируются.
- Закрытие терминала входа завершает подключение сразу: выполняется одна финальная проверка, и при выполненном
  входе аккаунт сохраняется, иначе показывается ошибка. Повторное «Добавить» доступно без ожидания таймаута.

Реализация: `src/services/codexAccountService.ts`, `src/services/claudeAccountService.ts`,
`src/providers/copilotUsagePanelManager.ts`.
Проверка: `tests/codexAccounts.test.ts`, `tests/claudeAccounts.test.ts`, `tests/claudeAccountsWindows.test.ts`,
`tests/accountsPanelManager.test.ts`.

## Codex

- При первом запуске добавляется текущий профиль из `CODEX_HOME/auth.json` (обычно `~/.codex/auth.json`).
- Добавление нового аккаунта выполняет `codex login --device-auth` в изолированном временном `CODEX_HOME`.
- Профили хранятся в VS Code SecretStorage; в webview передаются только названия и служебный статус.
- Активный профиль определяется по identity файла `auth.json` на диске, а не по сохранённой отметке окна:
  после переключения в другом окне название и лимиты совпадают, «Выбрать» прежний аккаунт снова работает.
- Выбор другого профиля атомарно подставляет его авторизацию в основной `auth.json` с возможностью восстановления
  прежней при ошибке. Текущая авторизация перед заменой сохраняется в секрет своего профиля.
- Работающий Codex App Server не перечитывает `auth.json` автоматически. Без адресного перезапуска отображается
  статус «ожидает применения». Если в Codex появится команда `chatgpt.restartAppServer`, переключатель использует её;
  иначе нужен явный перезапуск Extension Host (затрагивает другие расширения) или Reload Window.
- Вручную переключайте аккаунты только после завершения активных задач; автоматической ротации и обхода квот нет.
- Если установлен Codex Profiles или другое расширение, меняющее `auth.json`, используйте только один переключатель.

### Лимиты Codex

- Данные считываются отдельным процессом `codex app-server` методом `account/rateLimits/read` во временном
  `CODEX_HOME` с правами 0700, куда копируется текущий `auth.json`.
- App-server может обновить токены во время запроса, израсходовав прежний refresh token. Поэтому после ответа
  процесс штатно завершается (ожидание ограничено), и изменённый `auth.json` возвращается в основной файл —
  только для того же аккаунта и только если основной файл за это время не менялся; секрет профиля обновляется.
  Временный каталог удаляется в любом случае. Ошибки возврата пишутся в журнал без содержимого токенов.
  Каталоги `prompt-manager-codex-limits-*` и `prompt-manager-codex-login-*` во временной папке, оставшиеся после
  аварийного завершения Extension Host, удаляются при активации расширения: только каталоги текущего пользователя
  с точным шаблоном имени, старше 20 минут; символические ссылки пропускаются.
- Опрашивает только окно VS Code в фокусе (или кнопка «Обновить» в любом окне), не чаще раза в минуту; при получении
  фокуса окно обновляет данные. Результат сохраняется в общий файл кэша в `globalStorage` (ключ — sha256 identity,
  только проценты, сроки сброса, тариф и время получения). Остальные окна показывают его; данные старше 3 минут
  или после времени сброса помечаются «≈» и пометкой в подсказке.
- При ошибке отображается «лимиты —», а не вымышленные значения.

Реализация: `src/services/codexRateLimitService.ts`, `src/providers/codexAccountsStatusBarProvider.ts`.
Проверка: `tests/codexRateLimit.test.ts`, `tests/codexAccounts.test.ts`.

## Claude Code

- Нужен установленный Anthropic Claude Code. Данные авторизации проверяются официальной командой
  `claude auth status --json`.
- Основной профиль использует штатные `~/.claude` и `~/.claude.json`: явный `CLAUDE_CONFIG_DIR=~/.claude` меняет
  расположение части служебных данных, поэтому его не устанавливаем.
- Дополнительные профили создаются в globalStorage Prompt Manager, каждый со своим `CLAUDE_CONFIG_DIR` и входом
  `claude auth login`. Токены не копируются и не передаются в webview.
- Выбор профиля обновляет только `claudeCode.environmentVariables` в пользовательских настройках VS Code.
  Другие переменные сохраняются. При конфликте с настройками рабочей области или переменными авторизации
  переключение останавливается с предупреждением.
- Открытые процессы Claude не переключаются. Для новых процессов действует выбранная конфигурация; может
  потребоваться подтверждённый Reload Window.
- Пользовательские настройки, история и плагины в дополнительных каталогах изолированы. Проектные файлы `.claude/`
  остаются общими.
- Удаление созданного профиля, кроме основного, удаляет его каталог после подтверждения. Не удаляйте профиль,
  который использует другое окно.

### Лимиты Claude Code

- Основной источник — штатная команда Claude CLI `/usage` через
  `claude -p /usage --output-format json --no-session-persistence --max-turns 1 --tools ''`. Она проверена
  на Claude Code 2.1.327: ноль модельных обращений и нулевая стоимость. Prompt Manager не делает собственных
  HTTP-запросов к Anthropic и не читает OAuth-токены. Путь к CLI определяется при каждой проверке.
- CLI запускается в постоянном рабочем каталоге `<globalStorage>/claude-usage-cwd` (0700), поэтому в
  `~/.claude/projects` появляется один каталог этого пути, а не новый на каждую проверку. Пустые каталоги
  прежних проверок (`<ключ tmp>-pm-claude-usage-XXXXXX` только с пустым `memory`) удаляются один раз за запуск.
- Каждые **5 минут** проверку может инициировать только активное окно. Опросы всех окон и проектов синхронизированы
  глобальной **межпроцессной блокировкой** (атомарный `mkdir`) в `context.globalStorageUri/claude-usage-cache-v1`.
  Победивший процесс запускает Claude CLI, остальные немедленно пропускают запуск.
- Все окна читают **один глобальный дисковый кэш**; ключ вычисляется из каталога авторизации `CLAUDE_CONFIG_DIR`,
  а не локального идентификатора профиля VS Code. Нет отдельных проверок на каждый проект или для неактивных аккаунтов.
- В кэше хранятся только 5-часовые, общие недельные и, если CLI показывает, модельные лимиты, время сброса
  и служебные времена проверки. Данные приватного отчёта `/usage` (список сессий, путей и задач) не сохраняются.
- Статус-бар проверяет общий кэш каждые 20 секунд. В неактивных окнах Claude CLI не запускается. При возвращении
  фокуса обновление запускается, если прошло 5 минут.
- Кнопка «Обновить» разрешает принудительную проверку, но не чаще одного раза в минуту глобально. При сетевой ошибке
  сохраняется предыдущий кэш и действует общий backoff 5–30 минут. CLI-проверка ограничена 40 секундами,
  устаревшая блокировка восстанавливается после 120 секунд.

### Сборщик statusLine

- Запасные источники — локальный `statusLine` и `cachedUsageUtilization`: более свежие данные выигрывают.
  Через 15 минут значения помечаются `≈`; после времени сброса старые окна показываются `—`.
- Настройка `promptManager.claude.statusLineCollector` (по умолчанию включена) добавляет в `settings.json` каждого
  профиля запись `statusLine` со скриптом `prompt-manager-statusline.cjs`. Уже существующий собственный `statusLine`
  не заменяется. Скрипт читает только `rate_limits` из данных Claude Code и ничего не выводит.
- При выключении настройки или командой «Удалить сборщик statusLine Claude Code» (она же выключает настройку)
  из `settings.json` всех профилей снимается только запись с маркером `prompt-manager-statusline.cjs`.
  Запись выполняется с проверкой, что файл не изменился, атомарно, с сохранением прежних прав; символическая ссылка
  на `settings.json` остаётся ссылкой. Резервная копия `settings.json.bak-prompt-manager-statusline` не удаляется.

Реализация: `src/services/claudeUsageCli.ts`, `src/services/claudeUsageShared.ts`,
`src/services/claudeUsageService.ts`, `src/services/claudeStatusLineService.ts`,
`src/providers/claudeAccountsStatusBarProvider.ts`.
Проверка: `tests/claudeSharedUsage.test.ts`, `tests/claudeStatusLine.test.ts`,
`tests/claudeStatusLineCollector.test.ts`, `tests/claudeStatusBar.test.ts`.

## Кредиты GitHub Copilot

- Страница показывает процент **использованных** кредитов и прогресс-бар за текущий месячный период
  (0% — кредиты не израсходованы, 100% — квота использована).
- Данные (`used`, `limit`, `planType`, `lastUpdated`) берутся из существующего CopilotUsageService, используется
  его кэш (не старше 5 минут). Отдельных запросов к GitHub для полосы нет.
- Когда сервис использует локальные или расчётные данные вместо GitHub API, блок явно показывает «расчётные данные».
  При отсутствии данных об авторизации или лимите прогресс-бар не рисуется.
- Время следующего периода вычисляется по началу текущего месяца. Это **ориентир**, а не время сброса,
  подтверждённое GitHub. Когда период уже прошёл, старое использование не показывается как текущее.
- При переключении Copilot старые проценты скрываются до завершения синхронизации аккаунта.

Реализация: `src/utils/copilotCredits.ts`, `src/webview/copilotUsage/CopilotCreditsProgress.tsx`.
Проверка: `tests/copilotCredits.test.tsx`.
