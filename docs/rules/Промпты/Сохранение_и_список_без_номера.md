# Сохранение и список промптов

Номер задачи не назначен. Правила относятся к редактору и нескольким окнам VS Code,
работающим с одной папкой хранения, в том числе через туннель.

## Сохранение и переключение

- Cache-метка совместимого host/webview сохраняется при правках UI. Если метки различаются, допускается
  одна перезагрузка assets на панель; повторное несовпадение не блокирует доставку промпта.
  Параллельные ready используют одну попытку. Устаревшие bootId по-прежнему отбрасываются.

- Выбор main/process отправляется в хранилище промпта сразу при клике. Последующий cleanup читает
  актуальную вкладку из синхронного ref, поэтому быстрое закрытие не возвращает предыдущую вкладку.

- Перед переходом редактор ожидает незавершённое сохранение, затем повторно проверяет последний снимок формы.
  Правки, принятые за время записи, сохраняются до замены текущего промпта.
- При ошибке записи переход отменяется: черновик и признак несохранённых изменений остаются в редакторе.
- Фоновое название и описание сохраняются в той же очереди по UUID, что и ручные изменения.
  Актуальный промпт читается внутри очереди; генерация меняет только ещё не заполненные пользователем поля.

Реализация: `EditorPanelManager.persistPanelBeforeSwitch`, `persistPromptSnapshotForSwitch`,
`scheduleBackgroundAiEnrichment`. Проверки в `tests/editorPanelManager.test.ts` воспроизводят
новую ревизию во время записи, отказ сохранения при переключении и конкуренцию фонового названия с формой.

## Список и внешние изменения

- Начальный вид: название по возрастанию, группировка по статусу, краткий режим.
  Хост и webview используют общие defaults; сохранённые значения не заменяются при обновлении.
  Проверка: `tests/sidebarSelection.test.ts`, первый рендер и восстановление sidebar в браузере.
- Завершившееся чтение конфигурации, плана или отчёта применяется только для последнего события этой папки.
  Чтение старой папки не должно возвращать её строку после переименования.
- Фоновый обход не заменяет кеш, если после начала обхода кеш уже изменился или пришло файловое событие.
- `SidebarProvider.refreshList` публикует результат только последнего запроса обновления.
- Кнопка обновления в шапке вызывает `promptManager.refreshList` с принудительным чтением папок.
  Кеш памяти и `prompt-list.json` заменяются фактическим списком, даже если файловое событие пропущено.
  Обычные запросы, пришедшие во время ручного обновления, ожидают тот же проход.
  Если во время чтения пришли новые события, проход повторяется, но не более трёх раз;
  при непрерывных изменениях пользователь получает ошибку с предложением повторить обновление.
  Ошибка доступа к каталогу не считается пустым списком и не стирает прежний кеш.
- `promptUuid` остаётся стабильным при переименовании. Если кеш указывает на отсутствующую папку,
  поиск проверяет реальные конфигурации и восстанавливает открытие по UUID.
- Если сохранены две папки с одним UUID, выбор строки и открытие учитывают точное имя папки.
  Восстановление по одному UUID допустимо, когда ему соответствует единственная запись.
- Эхо собственной записи `config.json` игнорируется только при точном совпадении содержимого.
  Отличающаяся запись другого окна обрабатывается и в течение интервала подавления собственного события.
- `prompt-list.json` является восстанавливаемым кешем. Его записи упорядочены внутри экземпляра,
  файл заменяется целым JSON через временный файл. Это не межпроцессная транзакция сохранения промпта.

Реализация: `StorageService`, `SidebarProvider`. Проверки:
`tests/storageServiceContextFiles.test.ts`, `tests/storageServiceSidebarSearch.test.ts`,
`tests/sidebarProvider.test.ts`. Сценарии двух окон используют два экземпляра с общей временной папкой.

Запись промпта в общем хранилище сериализована по UUID. Перед записью расширение сверяет
исходную папку и идентификатор с конфигурацией на диске. Если папка успела сменить имя или уже
принадлежит другому промпту, сохранение старого снимка завершается ошибкой.

- Когда одна форма отправляет несколько сохранений во время переименования, очередь учитывает
  и возврат поля к прежнему значению. Отказ одной записи не отменяет правки, ожидающие в очереди.
- При чтении старой конфигурации миграция повторно проверяет содержимое под блокировкой и
  заменяет файл целиком. Если запись UUID недоступна, список, открытие по UUID и предпросмотр
  используют один идентификатор физической папки.
- Новый или импортированный промпт появляется в списке после записи всей папки. Папка и её файлы
  наследуют права по правилам целевого каталога, включая групповую политику доступа на Linux.
- История относится к физической папке промпта. Архивная запись сохраняет свои снимки и лимит
  истории, даже если её прежнее имя заняла другая задача. Восстановление снимка от исходного
  промпта сохраняет привязку импортированной копии к её собственному разговору Claude.

Очередь редактора проверяется в `tests/editorPanelManager.test.ts`, хранилище и история —
в `tests/storageServiceContextFiles.test.ts`.

## Сортировка по номеру задачи

- Пункт «Номер задачи» сравнивает числовые части строк без преобразования в Number: 2 < 10 < 170,
  ABC-2 < ABC-12; длинные числа не теряют точность, исходный номер и ведущие нули не изменяются.
- Пустые номера идут последними при asc и desc. При равенстве используются название и id.
- «Номер задачи + Дата создания» уточняет одинаковые номера датой создания, затем названием и id.
  Пустые номера также сравниваются по дате внутри последней группы; направление применяется к обоим ключам.
- Сортировка применяется до группировки и работает с архивными результатами; строка нового промпта
  остаётся сверху. Начальный режим — «Номер задачи + Дата создания» по возрастанию.
  Сохранённый выбор сохраняется в workspace и имеет приоритет над начальным режимом.

Реализация: `src/utils/sidebarSorting.ts`, `SidebarApp`, `FilterBar`.
Проверки: `tests/sidebarSorting.test.ts`, sidebar-тесты.

## Просмотр промпта при наведении

- Карточка показывает номер задачи как строку, название, текущий статус строки и полный сохранённый текст Markdown.
  Несохранённые правки редактора в просмотр не включаются; длинный текст прокручивается внутри карточки.
- Наведение не открывает редактор, не меняет выделение, не создаёт отчёт и не исправляет конфигурацию.
  Для чтения используется отдельный путь без `getPrompt`, `readConfig`, миграций и кеша списка.
- Identity включает имя папки, UUID и архив. Выход за папку хранения и ссылки на посторонние файлы отклоняются.
  Ответ применяется только к текущему запросу; закрытие, удаление строки и новая ревизия отменяют его применение.
- Одновременно открыта одна карточка. Задержки появления и ухода — 400 и 150 мс; текст не кешируется после закрытия.
  Автоматическая прокрутка при фокусе клавиатуры не отменяет ещё ожидающую подсказку.
- HTML не исполняется, изображения не загружаются, ссылки отображаются текстом. Escape закрывает карточку;
  F2 переводит фокус из строки в область просмотра. Прокрутка карточки не прокручивает список.

Реализация: `StorageService.getPromptHoverPreview`, `SidebarProvider`, `PromptHoverPreview`, `PromptHoverCard`.
Проверки: `tests/storageServiceHoverPreview.test.ts`, `tests/promptHoverPreview.test.ts`,
`tests/sidebarProvider.test.ts`; события наведения, фокуса и поздних ответов проверяются в браузере.

## Настройки виджетов редактора

- Порядок, колонки и сворачивание глобальны для рабочих областей; профили `single-column`
  и `two-columns` сохраняются независимо. Пустая колонка и явно пустая карта являются допустимыми значениями.
- Порядок разделов обеих вкладок, раскрытие только main и все настройки представления виджетов хранятся
  в пользовательских application-настройках VS Code. Раскрытие Process и его автоматические правила не меняются.
- Статические поля Docker/TODO, main-раскрытия и сворачивания карточек имеют независимые setting keys:
  два окна могут одновременно менять разные поля без перезаписи соседних значений.
- Массивы порядка и динамическая карта раскрытий сохраняются целыми значениями; конкурирующие изменения
  одного такого значения подчиняются обычным правилам Settings Sync, распределённой транзакции нет.
- Список «Быстрые команды» растёт по количеству строк и прокручивается вместе с «Обзором».
- Заголовок каждой категории, включая «Без категории», раскрывает и сворачивает её команды. Выбор хранится в `dashboardPreferences.expanded`. Поиск открывает совпадения, а при очистке возвращает прежнее состояние групп.
- `dashboardPreferences.quickCommands.items` хранит уникальные названия в выбранном порядке. Карты
  `quickCommands.categories` и `quickCommands.texts` связывают категории и тексты с названиями,
  `quickCommands.target` хранит агента. Старый клиент по-прежнему читает и меняет список строк.
  У старой фразы названием и текстом служит одна строка. В карте текстов хранятся отличия от названия,
  включая явно пустой текст. Шаблоны с одинаковым текстом могут иметь разные названия.
  Перенос меняет порядок внутри категории, категория меняется в форме команды.
  Записи переходного формата переводятся в строки после сохранения их категорий.
  При переименовании текст и категория старого имени сохраняются до записи нового списка.
  Перед записью расширение получает свежие application-настройки именно того клиента, который сохраняет команду.
  Независимые изменения полей объединяются. При конфликте одного поля форма показывает текущий текст
  и оставляет черновик для повтора. Незавершённую запись категории и текста расширение восстанавливает по журналу.
  Строковый список старого клиента не сообщает, произошло переименование или замена команды.
  Если привязка неоднозначна, прежний шаблон доступен в форме через «Восстановить прежний текст».
  Его использование требует явного выбора и успешного сохранения. Новая одноимённая фраза получает свой буквальный текст.
- «+» и карандаш открывают окно с названием, категорией и текстом. Кнопка переменной заменяет выделение
  или вставляет маркер у курсора. Enter в тексте добавляет строку. Ctrl+Enter и Ctrl+S сохраняют шаблон.
  Смена числа колонок оставляет редактор открытым. Лупа ищет по названию, тексту и категории.
  Из свёрнутого состояния «+» и лупа также раскрывают карточку. При скрытии поля фильтр
  продолжает действовать. Меню агента в шапке показывает его имя, в узкой карточке — значок чата со стрелкой.
- «Текущий» учитывает раскрытые панели встроенного чата, Codex и Claude Code в текущем окне и выбранные
  вкладки редактора. Начиная с VS Code 1.96 запрос доступных команд палитры проверяет видимость панелей
  на клиенте, в том числе при подключении через Tunnel. Условия команд Prompt Manager в палитре взаимно
  исключают друг друга. Раскладка активного окна и выбранная группа ограничивают поиск вкладок при
  наличии вынесенных окон. Если границы определить нельзя, доступна ручная вставка. На старых клиентах
  используются вкладки и доступное поле встроенного чата. Когда видно несколько разных агентов, виджет
  предлагает ручную вставку. OpenCode CLI выбирается явно. Команда вставляется без отправки.
  Успешная вставка или передача черновика провайдеру завершается без уведомления. Доступное расширению
  поле Copilot подтверждает вставку изменением текста. При скрытой модели успешный вызов сохраняет буфер.
  В настольном VS Code «Claude Code» и «Текущий» вставляют текст через буфер в поле открытого разговора.
  Если видны несколько разговоров Claude, чат закрыт или используется браузер, доступна ручная вставка.
  Запуск нового разговора остаётся отдельным действием редактора промпта.
  Индикатор привязан к названию команды и переживает сворачивание
  карточки. Виджет отправляет текст только после ответа хоста на актуальный запрос. Хост проверяет
  оставшийся срок до начала вставки. Такой обмен работает при разных системных часах клиента и сервера.
  Поведение VS Code описывают [фильтрация палитры](https://github.com/microsoft/vscode/blob/1.96.0/src/vs/workbench/contrib/preferences/browser/preferencesActions.ts#L85-L121)
  и [обновление признака видимости панели](https://github.com/microsoft/vscode/blob/8a14f0cc1b08d531eb83255ea3764ae22aa932b5/src/vs/workbench/services/views/browser/viewsService.ts#L89-L113).
- Окна заметки, команды и Bash-скрипта открываются по центру видимой панели «Обзор». При открытии из текстового поля мышью запоминаются курсор и выделение. После закрытия можно сразу продолжить ввод. При открытии с клавиатуры фокус возвращается на кнопку. Это правило действует и для Git Flow. Если до ответа расширения пользователь перешёл в чат или соседнюю вкладку, обновление формы и отложенное закрытие оставляют фокус там. В тексте команды и описании заметки отмена до исходного текста восстанавливает и исходные окончания строк. После этого окно закрывается без подтверждения.
  Они учитывают изменение ширины и прокрутку панели. В диалоге предпросмотра Ctrl+S сохраняет команду,
  Escape предлагает закрыть изменённый черновик. Ошибка записи оставляет форму открытой до повтора или отмены.
- «Предпросмотр» в окне команды показывает несохранённый текст после подстановки. Он обновляется при вводе,
  смене промпта и внешнем перемещении его папки. При ошибке причина видна прямо в окне. Просмотр сохраняет
  содержимое поля чата и буфера. Сохранить можно сам шаблон с переменными.
- При предпросмотре, вставке, копировании и переходе к ручной вставке используются одни значения. `{{workspacePath}}`
  и `{{workspaceRelativePath}}` относятся к основной папке Prompt Manager, второй путь считается от домашнего
  каталога пользователя расширения. `{{workspaceName}}` берётся из VS Code. `{{taskNumber}}`,
  `{{promptTitle}}` и `{{promptDirectory}}` относятся к открытому промпту. Подстановка однопроходная,
  неизвестные маркеры остаются буквальным текстом. Пустой шаблон, недоступное значение и смена промпта
  вызывают предупреждение и сохраняют содержимое поля чата и буфера. Проверки в `quickCommandsWidget.test.tsx`,
  `editorPanelManager.test.ts` и `stateService.test.ts`.
- Для передачи Desktop/Web/Tunnel и между устройствами нужны общая учётная запись, синхронизируемый профиль
  и категория Settings в Settings Sync. Локальная запись не означает подтверждения облачной доставки.
- Global-значения приоритетны. Workspace и затем localStorage читаются только как legacy-источники.
  Первый явный жест переносит недостающие значения; полный legacy-снимок снимается до частичного патча.
  Явный глобальный `null` означает сброс и завершённый перенос этого ключа; только отсутствие ключа допускает legacy.
  Открытие и resize не записывают defaults; поздняя Sync не заменяется старым workspace-снимком.
- Раскрытия Git разделены по репозиторию, текущей ветке и сравниваемым refs; явное `false` сохраняется.
  Черновики команд, выполняемые операции и индикаторы загрузки не являются настройками.
- Первый bootstrap не заменяет ранние локальные изменения. Внешние изменения настроек приходят отдельным
  сообщением; ожидающие и ошибочные локальные патчи накладываются на него без обратной записи.
  Новое действие вытесняет только пересекающиеся поля старых патчей до их ответа; независимые ошибки сохраняются.
- Во время drag внешний снимок ожидает завершения жеста; перестановка сохраняет фокус и DOM полей.
  Клавиатура использует стрелки и Home/End, Escape отменяет жест. Скрытые разделы остаются в порядке.
  Разделы и виджеты используют общие стили ручки, уменьшения/затемнения и полосы вставки.
- Записи сериализуются одной очередью и подтверждаются только после завершения. Ошибка видна в интерфейсе;
  текущий вид и политика загрузки сохраняются согласованными. После ошибки требуется повторить изменение.
  Внешний снимок не снимает ожидающие и ошибочные флаги загрузчиков; успех снимает только свою актуальную ревизию.
  Новое дерево webview начинает с подтверждённых настроек; отказ записи не выдаётся за сохранение.
- До замены HTML при повторном открытии, создании панели и обновлении bundle завершается очередь
  принятых dashboard-записей. После ожидания проверяется актуальность открытия; отказ не блокирует bootstrap.
- Когда в окне VS Code ровно две группы редакторов слева и справа, страница промпта скрывает «Обзор» и разделитель,
  если ширина соседней группы больше или равна ширине группы промпта. Форма занимает всю доступную ширину.
  При расширении группы промпта или закрытии соседней группы «Обзор» возвращается с прежними настройками и черновиками.
  При группах сверху и снизу, одной или трёх и более группах действует обычная компоновка.
- При разделении ранее подтверждённой одиночной группы пополам страница сразу освобождает место под форму.
  Для этого ширина должна за одно изменение уменьшиться вдвое с учётом округления, при прежней высоте и размере окна.
  Фактическую раскладку подтверждает VS Code. Если ровно половину ширины заняла боковая панель, «Обзор» вернётся после ответа.
  Ответ для прежней ширины не отменяет предварительное скрытие. Проверки — `promptEditorGroupLayout.test.ts` и `editorPanelManager.test.ts`.
- При видимом «Обзоре» форма сжимается до 300 px. Ниже 638 px общей ширины виджеты переходят под форму.
  Вертикальный режим использует `single-column`. Изменение ширины само по себе не сохраняет defaults.
- Git Flow открывается поверх виджетов с отступом 16 px справа. Если между началом панели и этим отступом
  помещается диалог шириной 800 px, его левый край совпадает с началом виджетов. Иначе он расширяется влево.
  Когда ширина редактора меньше 832 px, с обеих сторон остаётся по 16 px, а широкую таблицу можно прокрутить внутри.
- Разделитель между формой и виджетами занимает промежуток 18 px и показывается только при горизонтальной
  компоновке: линия по центру и отступы по 8 px до панелей. В покое линия 1 px едва заметна, при наведении,
  фокусе и перетаскивании — 2 px цвета темы. Он меняет долю ширины формы от суммы ширин обеих панелей;
  минимумы — 300 px формы и 320 px виджетов. Без сохранённой доли действует автоматическая ширина формы
  до 840 px; ручная доля этим пределом не ограничена. На ширине страницы ровно 638 px диапазон вырожден,
  и разделитель отключён.
- Доля хранится в application-настройке `promptManager.editor.panelSplitRatio` с точностью до четырёх знаков
  и действует для всех промптов, вкладок «Основное» и «Процесс» и рабочих областей. `null` — автоматическая ширина;
  некорректное значение читается как `null`. Отсутствие поля в сообщении не меняет сохранённую долю,
  перенос legacy-настроек ключ не создаёт. Узкое окно не меняет долю: после расширения соотношение восстанавливается.
- Перетаскивание показывает ширину без сохранения промпта и без отметки несохранённых изменений.
  Завершённый жест, изменивший ширину, записывается один раз; Escape, потеря фокуса окна, изменение размера окна,
  отмена указателя и потеря захвата отменяют жест без записи. Стрелки меняют ширину на 2% (Shift — 10%),
  Home/End выбирают края; серия нажатий сохраняется после отпускания клавиши. Enter и двойной щелчок
  возвращают автоматическую ширину.
- Во время жеста профиль колонок виджетов не переключается и данные виджетов не перезапрашиваются;
  после отпускания сетка измеряется один раз. Повтор отклонённого значения выполняет запись повторно:
  щелчок по разделителю, жест или серия клавиш, вернувшиеся к той же ширине, и нажатие на краю диапазона
  повторяют только отклонённую запись видимого значения и не перезаписывают сохранённую долю без ошибки.
  Начальная ширина жеста берётся в момент превышения порога перемещения.
- Меню «⋯» рядом с кнопкой обновления панели «Обзор» показывает все виджеты; отметка стоит у видимых.
  Снятая отметка скрывает виджет, «Показать все» возвращает все. Меню остаётся открытым при переключении,
  закрывается по Escape и щелчку снаружи. Скрытие — application-настройка
  `promptManager.dashboardPreferences.hiddenSections`, общая для рабочих областей и обеих ширин панели.
- Скрытый виджет не отображается, сохраняет место в порядке колонок и не загружает данные: расширение и webview
  учитывают его как свёрнутый при решениях о загрузке (включая AI review), но сохраняемое сворачивание не меняется.
  Снова показанный виджет загружается как раскрытый — только если данных нет или они устарели; свёрнутый остаётся
  свёрнутым. Скрытие учитывается расширением сразу при получении настроек, до завершения записи.
  Если скрыты все виджеты, панель показывает подсказку про меню «⋯».
- Позиция вкладки «Процесс» снимается до смены компоновки и восстанавливается в новом scroll-контейнере.
- Автоматическая статистика Docker зависит от пересечения блоков метрик и видимости страницы/панели.
  Повторные показы используют текущий запрос; скрытие запрещает новые замеры, но не прерывает отправленный.
- Завершение запроса после `dispose()` не возобновляет опрос. Ручные, начальные и событийные загрузки,
  а также периодическая проверка compose-топологии сохраняют прежнее назначение.

Реализация: `StateService`, `EditorPanelManager`, `EditorApp`, `PromptDashboard`, `PromptDashboardService`,
`PromptPanelSplitter`, `resolvePromptEditorLayout` (`src/utils/promptDashboard.ts`).
Проверки: `tests/stateService.test.ts`, `tests/editorPanelManager.test.ts`, `tests/editorApp.test.tsx`,
`tests/promptDashboard.test.ts`, `tests/promptDashboardComponent.test.tsx`, `tests/promptDashboardPreferences.test.ts`,

## Вид плана на вкладке «Процесс»

- Переключатель «Краткий / Полный» меняет только отображение: файл `plan.md` не изменяется.
  Новые промпты открываются в «Кратком» виде, старые состояния без сохранённого выбора — в «Полном».
- Явный выбор сохраняется для каждого промпта отдельной записью рабочей области `promptManager.editorPlanViewModes`
  по UUID вместе с идентификатором папки. Запись приоритетнее снимка расположения блоков, поэтому поздний или
  устаревший снимок при закрытии и переключении не возвращает прежний вид.
- Папки с одинаковым UUID, например копии `-1`, имеют независимый выбор. Ключ панели редактора для режима
  не используется. Первое сохранение и переименование обычным сохранением в редакторе переносят выбор вместе
  с состоянием редактора. Переименование при сохранении во время переключения промпта, закрытия вкладки,
  запуска чата и фоновой генерации названия выбор не переносит: промпт откроется с видом из состояния
  редактора или по умолчанию. После запуска чата идентификатор промпта не меняется.
- Код страницы редактора загружается заново при каждом открытии, а код расширения — только после перезагрузки окна
  или Extension Host. Расхождение возникает, когда файлы расширения обновляются на месте: сборка при разработке
  и синхронизация Tunnel; установка новой версии использует отдельный каталог.
  Изменение полей состояния или сообщений между ними требует новой метки
  `EDITOR_WEBVIEW_ASSET_VERSION`: прежний код расширения тогда сообщает о необходимости перезагрузки окна
  вместо незаметной потери выбранного вида.

Реализация: `getEditorPromptPlanViewModeKeys`, `moveEditorPromptPlanViewModeEntries` (`src/types/prompt.ts`),
`StateService.savePromptPlanViewMode` и `migratePromptEditorViewState`, сообщение `savePromptPlanViewMode`
в `EditorPanelManager` и `EditorApp`.
Проверки: `tests/editorPromptViewState.test.ts`, `tests/stateService.test.ts`, `tests/editorPanelManager.test.ts`.
