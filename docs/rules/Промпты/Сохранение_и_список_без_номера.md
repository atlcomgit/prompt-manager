# Сохранение и список промптов

Номер задачи не назначен. Правила относятся к редактору и нескольким окнам VS Code,
работающим с одной папкой хранения, в том числе через туннель.

## Сохранение и переключение

- Перед переходом редактор ожидает незавершённое сохранение, затем повторно проверяет последний снимок формы.
  Правки, принятые за время записи, сохраняются до замены текущего промпта.
- При ошибке записи переход отменяется: черновик и признак несохранённых изменений остаются в редакторе.
- Фоновое название и описание сохраняются в той же очереди по UUID, что и ручные изменения.
  Актуальный промпт читается внутри очереди; генерация меняет только ещё не заполненные пользователем поля.

Реализация: `EditorPanelManager.persistPanelBeforeSwitch`, `persistPromptSnapshotForSwitch`,
`scheduleBackgroundAiEnrichment`. Проверки в `tests/editorPanelManager.test.ts` воспроизводят
новую ревизию во время записи, отказ сохранения при переключении и конкуренцию фонового названия с формой.

## Список и внешние изменения

- Завершившееся чтение конфигурации, плана или отчёта применяется только для последнего события этой папки.
  Чтение старой папки не должно возвращать её строку после переименования.
- Фоновый обход не заменяет кеш, если после начала обхода кеш уже изменился или пришло файловое событие.
- `SidebarProvider.refreshList` публикует результат только последнего запроса обновления.
- Кнопка обновления в шапке вызывает `promptManager.refreshList` с принудительным чтением папок.
  Кеш памяти и `prompt-list.json` заменяются фактическим списком, даже если файловое событие пропущено.
  Обычные запросы, пришедшие во время ручного обновления, ожидают тот же проход.
  Если во время чтения пришли новые события, проход повторяется, но не более трёх раз;
  при непрерывных изменениях пользователь получает ошибку с предложением повторить обновление.
  Ошибка доступа к каталогу не считается пустым списком и не стирает прежний кеш.
- `promptUuid` остаётся стабильным при переименовании. Если кеш указывает на отсутствующую папку,
  поиск проверяет реальные конфигурации и восстанавливает открытие по UUID.
- Эхо собственной записи `config.json` игнорируется только при точном совпадении содержимого.
  Отличающаяся запись другого окна обрабатывается и в течение интервала подавления собственного события.
- `prompt-list.json` является восстанавливаемым кешем. Его записи упорядочены внутри экземпляра,
  файл заменяется целым JSON через временный файл. Это не межпроцессная транзакция сохранения промпта.

Реализация: `StorageService`, `SidebarProvider`. Проверки:
`tests/storageServiceContextFiles.test.ts`, `tests/storageServiceSidebarSearch.test.ts`,
`tests/sidebarProvider.test.ts`. Сценарии двух окон используют два экземпляра с общей временной папкой.

Открытие разных промптов в двух окнах не должно возвращать старые строки списка.
Одновременное изменение одного промпта в разных процессах не получает общей очереди или блокировки
от этих правил: каждый экземпляр имеет свою очередь, а файловые события доставляются асинхронно.
