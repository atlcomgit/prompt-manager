# Запуск OpenCode CLI

## Настройки и окружение

Цель `opencode-cli` отображается как «Opencode CLI». Требуется Linux-хост расширения, Bash,
OpenCode ветки 2 начиная с 2.1.4 и включённая интеграция оболочки терминала VS Code.
В Remote/Tunnel CLI устанавливается на хосте Extension Host. В браузере установка не нужна.

`autoStartOpenCodeChat` включается только явным `true` и по умолчанию равен `false`.
Он не зависит от флагов Copilot/Xdotool. Модель и разрешения OpenCode сохраняются;
Plan/Agent остаются инструкциями в тексте. Установки и обновления CLI автоматически не выполняются.

## Подготовка нового чата

Каждый запуск создаёт терминал и новый `ses_pm_...` session ID. Единственный выбранный проект задаёт `cwd`;
при нескольких проектах используется первый корень workspace. Список проектов остаётся в общем тексте.
Контекст собирают существующие `buildChatMessage` и `buildChatContextFiles`; выключенные Memory/CodeMap
не добавляют устаревшие инструкции.

Терминал получает отдельный loopback WebSocket-порт IDE-протокола OpenCode только в своём окружении.
Команда запуска задаёт `OPENCODE_EDITOR_SSE_PORT` и удаляет `CLAUDE_CODE_SSE_PORT` через `/usr/bin/env`
непосредственно у процесса CLI. OpenCode предпочитает переменную Claude, а коллекции окружения расширений
VS Code применяются после `TerminalOptions.env`; одного `null` в настройках терминала недостаточно.
Настройки Claude и окружение других терминалов не меняются.
Файлы добавляются уведомлением `at_mentioned` с абсолютным путём: пробелы и спецсимволы не требуют
поиска через автодополнение. Вложение включает содержимое файла, а не только строку `#file:`.
Метка `#1` означает начало с первой строки: при равных `lineStart` и `lineEnd` OpenCode не задаёт конец диапазона.
В версии 2.1.4 штатный `at_mentioned` требует оба номера и всегда добавляет метку начальной строки.
Соединения с браузерным Origin не принимаются. Сервер не публикуется в сети и не передаётся другому чату.

Каждый файл начинается с отдельной строки. После каждого native-упоминания передаётся отдельная защищённая
вставка перевода строки, и следующий файл либо текст ждёт появления пустой строки ввода. Начальный перенос
нельзя объединять с длинным промптом: перед сворачиванием такой вставки OpenCode удаляет крайние пробелы и переносы.
Без файлов текст передаётся без дополнительной пустой строки; Enter при подготовке не отправляется.

Bash выполняет `exec` с экранированными аргументами. После готовности TUI текст передаётся защищённой
многострочной вставкой. ESC и другие управляющие символы отклоняются до открытия терминала.
Задача не становится shell-кодом; после выхода OpenCode управляющая оболочка не остаётся принимать текст.
Готовность проверяется по IDE handshake и отрисованному полю чата, а не фиксированной паузой.
Необязательные режимы paste/cursor/synchronized output не являются условием готовности: frontend терминала
может не передавать эти маркеры. После вставки ожидается новый текст или плейсхолдер OpenCode `[Pasted ~N lines]`;
кадр анимации сам по себе не разрешает автоматическую отправку.

Вывод TUI является набором изменений ячеек, а не последовательностью полных строк. Проверки файлов и вставки
восстанавливают экран через `@xterm/headless`: простое удаление ANSI теряет неизменившиеся буквы и переносы.
До exec оболочка передаёт размер PTY служебным OSC; экран не хранит scrollback, освобождается сразу после
подготовки и не обрабатывает последующие ответы модели. При закрытии отменяется и незавершённый разбор вывода.

При стандартной настройке OpenCode длинный текст виден как `[Pasted ~N lines]`. Нажатие на эту метку
раскрывает содержимое в поле; свёрнутое представление не означает отсутствие текста или файлового вложения.
При `prompt.paste: "full"` начало длинного текста скрывается прокруткой. Готовность допускает новое видимое
окончание последней строки; сам факт отправки по-прежнему требует полного текста в экспорте точной сессии.

## Отправка и подтверждение

При выключенном автостарте запрос остаётся в поле, отправка выполняется вручную.
При включённом флаге отправляется один Enter. Команда `opencode --prompt` для черновика не используется:
OpenCode 2.1.4 автоматически отправляет её содержимое.

Терминальный OSC-сигнал служит только поводом проверить экспорт назначенной сессии.
Подтверждение требует совпадения session ID, каталога и настоящих файлов; для автостарта также проверяется
полный текст запроса. Отсутствие подтверждения не вызывает повторной отправки и не очищает план.
После подтверждённой ручной отправки допускается отредактированный текст, но сохраняется проверка файлов.
Старая или уже закрытая/архивная задача не принимает поздние события другой цели.
Подтверждение ручной отправки относится к поколению запуска. Координатор меняет поколение при принятии
следующего старта, до ожидания контекста и hooks; сервис — до проверок CLI. После await повторно проверяются
оба поколения, включая чтение промпта и stat плана. Неудачный новый старт не возвращает старому чату право
очищать актуальный план, даже если его терминал остаётся доступен для навигации.

Открытие терминала, успешный `sendText` и подготовка черновика сами по себе не являются отправкой.
План очищается и события начала запроса публикуются только после подтверждения; отчёт сохраняется.
Ошибка до отправки возвращает исходный статус, не отменяя явно выбранное позднее состояние.
Таймаут подготовки оставляет терминал открытым для диагностики и перехода. Сообщение различает отсутствие
shell integration, IDE-соединения и отрисовки; журнал содержит этап и session ID без текста и путей контекста.

## Переход, остановка и ресурсы

«Перейти в чат» выбирает терминал по UUID, а не заголовку или текущему фокусу, без повторного запроса.
Восстановленный доступный терминал выбирается по сохранённой метке; при нескольких запусках — последний.
В активном сеансе расширения после закрытия последнего запуска старый чат не подставляется вместо него.
Остановку выполняют в самом OpenCode; смена статуса не останавливает CLI и не отправляет Stop в Copilot.
Автоматический импорт времени, стоимости и истории OpenCode не выполняется; прежние значения не обнуляются.

Подписки, ожидания и собственный IDE-сервер освобождаются при закрытии или dispose.
Перезагрузка расширения не закрывает работающие пользовательские терминалы. После потери IDE-соединения
отправка из самого TUI остаётся доступной, но прежний обработчик подтверждения больше не наблюдает её.

- Проверки команды запуска выполняют настоящий Bash с конфликтующим портом Claude; сервис проверяется
  без необязательных режимов терминала, с асинхронной вставкой и таймаутом без закрытия терминала.
- Регрессии покрывают два похожих имени инструкций, частичную перерисовку, перенос метки вставки,
  очистку прежних строк и освобождение экрана до ручной отправки. Порядок file → newline → file → newline → prompt
  проверяется отдельно; следующий элемент ждёт завершения асинхронной вставки переноса.
- Поздние ручные подтверждения проверяются при ожидании beforeChat, подготовки нового CLI, lookup и stat,
  а также после отказа нового старта. Полная вставка проверяется с началом, скрытым за прокруткой поля.
- Проверять реальный терминал отдельно от mock/SSR: черновик без отправки, отправку одного полного запроса,
  файлы с содержимым, длинный русский текст, параллельные терминалы, закрытие и переход.
