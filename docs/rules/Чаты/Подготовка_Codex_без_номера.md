# Подготовка черновика OpenAI Codex

## Назначение и текущее поведение

В локальном desktop VS Code Prompt Manager передаёт полный текст задачи в редактируемое поле Codex.
В VS Code Web поле заполнить нельзя, поэтому полный текст передаётся файлом запроса, прикреплённым к новому чату.
Успешное открытие панели, запись в буфер и выполнение команды прикрепления файла не подтверждают заполнение поля,
показ файла или отправку сообщения.

- В локальном desktop VS Code используется `editor.action.clipboardPasteAction`.
  Длинный текст делится на части, чтобы не превращаться во вложение; план сохраняется без подтверждения отправки.
- В VS Code Web/Tunnel полный текст записывается в файл `task.md` папки промпта и прикрепляется
  к новому чату командой `chatgpt.addFileToThread`; текст также записывается в буфер обмена.
  Поле сообщения остаётся пустым, для запуска пользователь нажимает «Отправить». Код не меняет установленный Codex.
- Если команды `chatgpt.addFileToThread` нет, промпт ещё не сохранён или запись файла либо команда завершились ошибкой,
  Prompt Manager сообщает о ручной вставке текста из буфера обмена.
- Xdotool разрешён только для локального Linux desktop. Клавиши на сервере не управляют браузером клиента.

## Файл запроса в VS Code Web

Сообщение Codex с прикреплённым файлом и пустым полем содержит только ссылку на файл
(раздел `# Files mentioned by the user:`) и пустой текст запроса. Поэтому файл устроен так:

- первая строка объясняет модели, что файл содержит полный текст запроса пользователя и его нужно выполнить;
  язык строки следует языку интерфейса VS Code;
- после разделителя `---` идёт текст задачи без каких-либо изменений;
- файл прикрепляется первым, перед файлами контекста промпта;
- файл заменяется при каждом запуске из браузера и не удаляется после запуска:
  Codex читает его по пути уже после отправки сообщения.

Запуск с файлом запроса не считается отправкой: план промпта не очищается, `agent.json` не создаётся.

### Порядок и ожидания

- Codex применяет «Новый чат» асинхронно и сбрасывает поле вместе с уже добавленными файлами.
  Файл, отправленный одновременно с командой нового чата, теряется; при интервале от 30 мс он сохраняется.
  Prompt Manager ждёт 600 мс после `chatgpt.newChat` и только затем прикрепляет файлы.
- Пока панель Codex не загрузилась, Codex ставит команды в очередь и после загрузки применяет файлы раньше
  нового чата. Новый чат, пришедший после файлов, сбрасывает их: при запуске со скрытой, ещё не загруженной
  панелью все файлы терялись, хотя команды выполнялись без ошибок. Загрузка панели в туннеле занимает 8–15 секунд.
- Признака готовности панели для других расширений Codex не предоставляет, а повторное прикрепление того же файла
  не дублирует. Поэтому первый запуск в сеансе расширения повторяет прикрепление всех файлов в том же порядке
  каждые 3 секунды в течение 15 секунд после команды нового чата; файл запроса остаётся первым.
- После первого запуска панель считается загруженной до конца сеанса: следующие запуски прикрепляют файлы один раз.
  Если панель Codex была пересоздана в том же сеансе, файлы могут не сохраниться: тогда текст вставляют из буфера обмена.
- Повтор выполняется до завершения запуска, пока Prompt Manager показывает шаг открытия Codex. Отправка сообщения
  до завершения запуска оставит повторно прикреплённые файлы в поле следующего сообщения.

### Буфер обмена в браузере

В проверке в vscode.dev запись в буфер обмена не завершалась, пока запуск ждал её до открытия Codex
в неактивном окне браузера, и запуск останавливался на шаге открытия Codex. После перехода фокуса в панель Codex
запись завершалась.
В Web запись начинается до открытия Codex и ожидается не дольше 2 секунд; запуск от неё не зависит.
Сообщение упоминает копирование только после подтверждённой записи, иначе предлагает скопировать текст вручную.
На desktop запись ожидается полностью, потому что текст вставляется из буфера.

## Границы штатных интерфейсов

`vscode.env.clipboard` обращается к буферу клиента, включая удалённые рабочие области.
Запись в буфер не вставляет его содержимое в чужой webview.
Это разделение описано в [документации Remote Development](https://code.visualstudio.com/api/advanced-topics/remote-extensions#using-the-clipboard).

Команда вставки для webview вызывает `execCommand('paste')`. В VS Code остаётся открытой
[задача перехода webview на браузерный механизм вставки №239228](https://github.com/microsoft/vscode/issues/239228).
Обычные поля интерфейса и редактор кода имеют отдельные обработчики; их успешная вставка не доказывает работу Codex.

Команды `type` и `default:type` вызывают обработчик активного редактора кода и не вводят текст
в произвольный webview: [реализация EditorHandlerCommand](https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/coreCommands.ts).

В проверенной версии Codex 26.1111.21308:
- `chatgpt.newChat` открывает чат без аргумента с текстом.
- `chatgpt.addToThread` и `chatgpt.addFileToThread` добавляют контекст файла или выделения.
- `chatgpt.implementTodo` отправляет преобразованный запрос и не подходит для подготовки точного черновика.
- Внутренний prefill не является публичной командой расширения.

### Обработчик ссылок Codex

Расширение Codex регистрирует обработчик ссылок `vscode://openai.chatgpt/<маршрут>?<параметры>` (`onUri`).
Он открывает панель и переводит её на указанный маршрут вместе с параметрами запроса;
состояние маршрута, в котором Codex хранит текст для заполнения поля (`prefillPrompt`), ссылкой не передаётся.

- В VS Code Web такую ссылку доставляет команда `vscode.open`: она передаётся обработчику расширения
  без диалога подтверждения ([BrowserURLOpener](https://github.com/microsoft/vscode/blob/69047191fc427f2f92828279aae1d90d8eeda7ab/src/vs/workbench/services/url/browser/urlService.ts)).
  `vscode.env.openExternal` в Web внутрь окна ссылку не доставляет.
- В Codex 26.1111.21308 параметры `prompt`, `promptSource`, `q` и фрагмент `#prompt` поле не заполняют.
  Результат одинаков при переходе с домашнего экрана и с другого экрана (`/skills` → `/`).
  Разбор параметра `prompt` в коде поля присутствует, но значение из ссылки в эту сборку не передаётся.
- По коду webview маршрут плагина с параметрами `install` и `prompt` добавляет к тексту упоминание плагина
  и для передачи точного текста задачи не подходит; в браузере этот маршрут не проверялся.

Команда `chatgpt.newChat` берёт текст только из внутреннего хранилища передачи черновика,
которое заполняет сам webview Codex. Расширение не регистрирует поставщика содержимого чата
и участника встроенного чата VS Code, поэтому встроенное поле ввода VS Code для него недоступно.

В Web `chatgpt.addFileToThread` прикрепляет файл к новому чату, после чего отправка доступна при пустом поле.
Прикрепление файла вместо текста не считается заполнением поля.

Повторная проверка нужна после обновления Codex: появление значения `prompt` из ссылки
или аргумента с текстом у публичной команды делает заполнение возможным через `vscode.open` либо эту команду.

Публичные команды перечислены в [справочнике IDE](https://learn.chatgpt.com/docs/developer-commands?surface=ide).
Ссылки `codex://new?prompt=...` документированы для
[настольного приложения](https://learn.chatgpt.com/docs/reference/commands#deep-links);
они не предоставляют API заполнения поля расширения внутри vscode.dev.

## Проверки

Реализация: `EditorPanelManager.dispatchCodexChatTarget`, `writeCodexRequestFile`, `attachCodexChatFiles`,
`writeClipboardTextWithTimeout`, `prepareCodexPrompt`,
`pasteCodexClipboardText`, `splitCodexPasteText`, `buildCodexRequestFileContent`.
Автотесты: `tests/editorPanelManager.test.ts`, `tests/codexClipboard.test.ts`, `tests/codexRequestFile.test.ts`.

При изменении интеграции проверять в настоящем `vscode.dev/tunnel` короткий и длинный текст,
русский язык, Markdown, Unicode, выбранные файлы и отсутствие отправки при подготовке.
После обновления VS Code или Codex повторно проверять фактические команды и браузерные возможности.
Успех теста отказа, внутреннего prefill через DevTools или записи в clipboard не является проверкой полного запуска.
